# Prototype comparison and MVP decisions

Reference: [Christy’s Spotmark prototype](https://acad325.hylstudio.work/project1/), observed in the browser on 2026-11-24. The comparison describes visible screens and interactions; it does not establish that disconnected integrations, accounts, or every displayed action have working backends. In particular, the Claude connection was shown as disconnected.

DanceForm’s MVP priority is reliable laptop formation editing and useful mobile rehearsal communication: named dancers, measured positions and cones, editable saved travel, musical counts, real audio, revisions, and count-anchored notes. Matching every prototype panel would dilute that work.

| Area observed in Spotmark                               | Current DanceForm                                                                                                                                                   | MVP decision and reason                                                                                                                                                                                                                                                             |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Dashboard, teams, people and profile screens            | Persistent projects and a project-specific named roster; owner session and capability-based rehearsal access                                                        | **Keep projects and roster. Defer organization/account administration.** The local prototype is not a multi-tenant team service; individual verified membership needs a separate identity and authorization design.                                                                 |
| Multiple songs in a choreography                        | One optional real audio asset per project, with tempo, offset and count-only rehearsal                                                                              | **Keep one-song/count workflow. Defer multi-song arrangement.** Multiple clips need explicit ordering, offsets, gaps and timing rules rather than decorative song tabs.                                                                                                             |
| New, duplicate and delete formations                    | Formation CRUD, quarter-beat arrival controls, draggable strips, saved transitions and undo/redo                                                                    | **Keep. Implemented.** These are necessary rehearsal iteration tools. Neighboring timing and approved-route constraints must survive edits.                                                                                                                                         |
| Fixed 2/4/8/16 transition choices and count controls    | Numeric quarter-beat travel duration, draggable transition start/body, global eight-count display, section focus and loop                                           | **Keep precise counts and durations.** DanceForm supports these durations through a more general count model; a preset selector is optional convenience, not a new motion model.                                                                                                    |
| 2D and 3D views, height visibility and blocking         | Measured 2D stage, orientation, grid, zoom/pan, named dancers and stage reference cones                                                                             | **Keep 2D; defer 3D and height-aware blocking.** Height models, occlusion and camera behavior need validated physical semantics. No height-based clearance claim is made.                                                                                                           |
| Roster heights, skills and accounts                     | Stable dancer IDs, names, display colors and project placements                                                                                                     | **Keep identity/placements; defer skills and height profiles.** Those fields should serve an actual planning decision before increasing roster complexity.                                                                                                                          |
| Cones and reference objects                             | Traffic-cone iconography and persisted reference cones; add, rename, remove, numeric, drag and keyboard movement                                                    | **Keep. Implemented.** Dancers orient against real stage marks as well as people.                                                                                                                                                                                                   |
| Crossings, blocked positions and timeline review        | Saved linear/smooth trajectories, time-aware clearance, speed and boundary review markers linked to counts                                                          | **Keep timed review. Implemented with limits.** A geometric crossing at different times differs from a simultaneous overlap. Review warnings are rehearsal prompts, not safety certification or a guarantee that every issue is found.                                              |
| AI rules panel and disconnected Claude integration      | Bounded deterministic transition suggestions, editable anchors, route locks and infeasibility/review feedback                                                       | **Keep deterministic assistance; defer AI chat/rules.** Suggestions support a choreographer’s transition work. No learned motion generation, automatic choreography or connected Claude feature is claimed.                                                                         |
| Dancer mode with music, counts, mirror and video        | Find me, selected route, current stage coordinates, nearby dancer distances, next formation/count; real music/count playback and notes                              | **Keep practice essentials. Defer mirrored video and recording workflows.** Video needs permissions, orientation, storage and synchronization work beyond displaying a camera button.                                                                                               |
| Personal spot cards with counts, neighbors and distance | Mobile Home spot card with selected dancer, current count/position, next formation/count and nearby center-to-center distances; landscape stage and Tools inspector | **Keep. Implemented.** These answer concrete rehearsal questions. They do not calculate a dancer’s real-world location or guarantee clearance.                                                                                                                                      |
| Image/text sharing                                      | Published revision and reader capability link; notes and explicit revision acknowledgment; clipboard error feedback                                                 | **Keep actual revision sharing. Defer image/text exports.** A rehearsal link should identify the current published plan; exports need revision/count labels and a tested rendering path. Reader-link browser QA remains blocked by the earlier approval review and was not retried. |
| Offstage entry/exit concepts                            | Core position metadata supports intentional offstage states, but the bounded stage UI has no complete offstage authoring workflow                                   | **Defer the UI workflow.** A flag alone would hide the need for visible offstage space, editable entry/exit marks and consistent route handling.                                                                                                                                    |
| Metronome and richer rehearsal cues                     | Musical count transport and genuine count-anchored rehearsal notes; no metronome sound                                                                              | **Keep notes/counts. Defer audible metronome.** Audio mixing, timing and mobile interruption behavior need dedicated validation.                                                                                                                                                    |

The implemented motion distinction is explicit: **Straight** follows saved linear segments; **Smooth** uses the same canonical sampled trajectory for rendering, playback and review. A two-anchor smooth route remains visually straight; adding or dragging a waypoint shapes a curve. Approved routes remain locked until explicitly unlocked. New recommendations can choose checked smooth detours without silently migrating approved legacy routes.

The web editor now uses a light purple stage workspace and a dark charcoal timeline with lavender formation chips, purple waveform/actions and amber review markers. Mobile web offers portrait Home/Notes/Projects and a landscape stage with a full Tools inspector. The native client shares the project model and evaluator but deliberately has a lighter editing surface than the laptop editor.

## Evidence and limits

The final web build, native TypeScript check and **45 focused tests** pass. Browser checks covered project settings, section split/remove, cone CRUD/numeric/keyboard movement and Undo, in-app dancer addition/removal with Undo/Redo, waypoint/Smooth/lock behavior, count playback, a beat-12 saved note, whole-formation drag with Undo, and transition resize with Undo. The detailed distinction between browser checks, automated model tests and source review is in [web-control-audit.md](web-control-audit.md).

Audio import remains a manual browser check because file-chooser automation failed twice; this is not an assertion that import failed. Reader-link browser testing was blocked by an earlier automatic approval review and was not retried. Final mobile-web portrait/landscape Tools browser checks were not completed after browser access was declined; those changes have source/test/build evidence only. Earlier browser checks listed above passed before that denial. Physical iOS/Android orientation, touch, audio-device/interruption behavior and release builds remain pending. No server tests were run as part of this comparison pass.
